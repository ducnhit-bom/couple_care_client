# Flutter Bootstrap Plan

## Goal

Implement a new Flutter base app under `frontend/` with:

- App display name: `Couple`
- Dart package/project name: `couple`
- Organization / bundle prefix: `com.thenextbuild.couplecare`
- Firebase setup: placeholder-first only, with no live credentials committed

## Phase 1 - Create project scaffold in `frontend/`

### Actions

1. Create the app under `frontend/` with Flutter stable:
   ```bash
   flutter create --project-name couple --org com.thenextbuild.couplecare --platforms android,ios,web frontend
   ```
2. Confirm generated identifiers align with `com.thenextbuild.couplecare.couple`.
3. Update display metadata so the human-facing app name is `Couple`.

### Exit criteria

- `frontend/` exists as a valid Flutter app
- `frontend/pubspec.yaml` uses `name: couple`
- Android/iOS/Web display name reads `Couple`

## Phase 2 - Replace default app with bootstrap architecture

### Actions

1. Remove the sample counter implementation.
2. Add a minimal feature-first structure with app shell, theme, config, and a placeholder home page.
3. Keep the app runnable with no backend credentials.

### Target structure

```text
frontend/lib/
├── app/
│   ├── app.dart
│   ├── bootstrap.dart
│   └── router/
│       └── app_router.dart
├── core/
│   ├── config/
│   │   ├── app_config.dart
│   │   ├── environment.dart
│   │   └── firebase_config.dart
│   ├── providers/
│   │   └── core_providers.dart
│   └── theme/
│       └── app_theme.dart
├── features/
│   └── home/
│       └── presentation/
│           └── pages/
│               └── home_page.dart
├── firebase_options.dart
└── main.dart
```

### Exit criteria

- App launches to a simple `Couple` home screen
- No sample counter code remains

## Phase 3 - Add core dependencies and project rules

### Actions

1. Add bootstrap dependencies only:
   - `flutter_riverpod`
   - `go_router`
   - `firebase_core`
2. Add dev tooling:
   - `flutter_lints`
   - `custom_lint`
   - `riverpod_lint`
3. Replace lint config with repo-ready analyzer settings.

### Exit criteria

- `flutter pub get` succeeds
- `flutter analyze` has no bootstrap configuration issues

## Phase 4 - Implement environment and app config

### Actions

1. Add a small environment layer using `--dart-define`.
2. Define safe defaults for bootstrap-only values.
3. Separate runtime config from Firebase config so the app can run before real setup.

### Required config shape

- `APP_NAME=Couple` defaulted in code if omitted
- `FLAVOR=dev` defaulted in code if omitted
- `ENABLE_FIREBASE=false` defaulted in code if omitted

### Exit criteria

- App reads config without crashing when no defines are supplied

## Phase 5 - Add placeholder-first Firebase integration

### Actions

1. Create a checked-in placeholder `firebase_options.dart` with obvious stub values.
2. Add a Firebase wrapper that only initializes Firebase when `ENABLE_FIREBASE=true`.
3. Keep native Firebase plugin wiring out of the placeholder phase.
4. Do not add live `google-services.json` or `GoogleService-Info.plist`.
5. Document the handoff path using `flutterfire configure` for future integration.

### Placeholder rules

- Use stub `FirebaseOptions` values only
- Add comments stating the file must later be replaced/generated by FlutterFire
- Do not add Google services Gradle or Xcode/Pod wiring while placeholder mode is active
- Ensure iOS placeholder bundle id matches `com.thenextbuild.couplecare.couple`

### Exit criteria

- Bootstrap compiles with placeholder Firebase code present
- App startup does not initialize Firebase unless explicitly enabled
- No real Firebase credentials exist anywhere in `frontend/`

## Phase 6 - Wire navigation and startup flow

### Actions

1. Add `ProviderScope` at the root.
2. Add `go_router` with a minimal route table.
3. Route `/` to the initial home/bootstrap page.

### Exit criteria

- App starts through Riverpod + router successfully
- `/` renders the placeholder home page

## Phase 7 - Align platform branding

### Actions

1. Verify Android app label is `Couple`.
2. Verify iOS display name is `Couple`.
3. Verify web manifest/title uses `Couple`.

### Exit criteria

- Installed/running app shows `Couple` on all bootstrapped platforms

## Phase 8 - Basic test and verification hardening

### Actions

1. Replace the default widget test with a bootstrap smoke test.
2. Ensure the app can be pumped without live Firebase or network state.
3. Add a short README note for local bootstrap commands and placeholder Firebase behavior.

### Exit criteria

- Test reflects the real bootstrap app instead of the counter sample

## Verification Steps

Run from repo root:

```bash
flutter --version
flutter pub get --directory frontend
flutter analyze frontend
flutter test frontend
flutter build apk --debug --target-platform android-arm64 --directory frontend
flutter build web --directory frontend
```

## Verification Checklist

- [ ] `frontend/` is a standalone Flutter app
- [ ] `frontend/pubspec.yaml` uses `name: couple`
- [ ] Android/iOS/Web product name is `Couple`
- [ ] Application id prefix resolves to `com.thenextbuild.couplecare.couple`
- [ ] Placeholder `frontend/lib/firebase_options.dart` exists
- [ ] App does not initialize Firebase when `ENABLE_FIREBASE` is omitted or `false`
- [ ] No live Firebase credential files are committed
- [ ] `flutter analyze frontend` passes
- [ ] `flutter test frontend` passes
- [ ] App boots to a non-sample screen
- [ ] Router and Riverpod root wiring compile and run

## Out of Scope

- Real Firebase project binding
- Production flavors
- API client implementation
- Auth flows
- Feature modules beyond the bootstrap home screen
